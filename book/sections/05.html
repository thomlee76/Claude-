Claude Code для не-программиста: автоматизация документов и данных

Из этого раздела вы узнаете, как поручать Claude Code рутину, которую сейчас делаете руками или отдаёте ассистенту: сборку еженедельного отчёта из пяти Excel-файлов, наведение порядка в папке с документами Seoul Medical Center, пакетную генерацию коммерческих предложений в PDF и простую веб-страницу для дистрибьюторов. Программировать не нужно: вы описываете результат словами, Claude Code сам пишет и запускает скрипты. Ваша задача — правильно поставить задачу, выбрать режим разрешений и проверить результат.

Что такое Claude Code и зачем он руководителю продаж

Вывод сразу: Claude Code — это не чат, а исполнитель. В обычном чате Claude отвечает текстом, а вы копируете результат в Excel или Word. Claude Code работает прямо с файлами на вашем компьютере (или в облаке): открывает таблицы, пишет небольшие программы на Python, запускает их, проверяет результат, переименовывает и раскладывает документы, создаёт PDF и веб-страницы. Официальная документация описывает его как агентный инструмент, который читает проект, редактирует файлы, выполняет команды и подключается к вашим рабочим инструментам.

Изначально продукт создан для разработчиков, но для руководителя отдела продаж у него есть четыре очень практичных применения:

  • Автоматизация Excel-отчётов. Пять выгрузок от дистрибьюторов и бухгалтерии превращаются в один сводный отчёт по продажам и дебиторке — каждую неделю одной командой, без ручного копирования.
  • Пакетная обработка файлов. Сотни сканов, договоров, спецификаций и актов по проекту SMC переименовываются по единому шаблону и раскладываются по папкам «Поставка», «Монтаж», «Обучение», «Финансы».
  • Конвертация и генерация документов. Из одной таблицы с дистрибьюторами и одного шаблона получается десять персональных коммерческих предложений в PDF на русском и английском.
  • Мини-сайты и калькуляторы для партнёров. Страница с каталогом оборудования, условиями поставки и калькулятором цены со скидкой, которую можно отправить ссылкой дистрибьютору в Ташкенте или Сан-Паулу.

Главное отличие от макросов Excel и от «попросить айтишника»: вы не формулируете техническое задание. Вы пишете то же, что сказали бы толковому аналитику: «Собери из этих пяти файлов отчёт, как в прошлый понедельник, и проверь, что итоги сходятся». Claude Code задаст уточняющие вопросы, покажет план, сделает работу и объяснит, что получилось.

Важно знать. Claude Code требует платного аккаунта: Pro, Max, Team, Enterprise или Console (API). Бесплатный план claude.ai доступа к Claude Code не даёт. Если у вас корпоративный план Team или Enterprise, уточните у администратора, включён ли Claude Code в ваше место (seat).

Как это работает: агент, который действует, а не только советует

Представьте, что вы наняли ассистента-аналитика, посадили его за свой компьютер и открыли ему одну рабочую папку. Он видит только эту папку, умеет пользоваться командной строкой и Python, а перед каждым рискованным действием спрашивает: «Можно?» Примерно так и устроен Claude Code.

Работа идёт циклом из четырёх шагов:

  1. Понять задачу и контекст. Claude читает ваш запрос, файл памяти проекта CLAUDE.md (о нём ниже) и нужные файлы в папке.
  2. Спланировать. Для сложной задачи Claude сначала составляет план: какие файлы прочитать, какой скрипт написать, как проверить результат.
  3. Действовать. Claude вызывает инструменты: читает и редактирует файлы, запускает команды. Что из этого делается без вашего подтверждения, определяет режим разрешений.
  4. Проверить и доложить. Claude смотрит на результат команды, исправляет ошибки и сообщает итог: что сделано, где лежат файлы, что требует вашего внимания.

Важная деталь для не-программиста: Claude Code часто решает задачу, написав маленькую программу. Например, для сводного отчёта он создаёт файл weekly_report.py. Это хорошо: скрипт остаётся в папке, и в следующий понедельник его можно просто запустить снова — быстро, одинаково и без повторной траты лимитов на «размышления». Вы не обязаны понимать код, но полезно попросить Claude объяснять каждый скрипт простыми словами и писать комментарии на русском.

Каждая сессия начинается «с чистого листа»: Claude не помнит прошлых разговоров, кроме того, что записано в CLAUDE.md и в автоматической памяти проекта. Поэтому правила, которые важны всегда (валюта отчёта, формат чисел, куда нельзя записывать), выносите в CLAUDE.md, а не повторяйте в каждом запросе.

Где работает Claude Code

У Claude Code один «движок» и несколько поверхностей (см. рис. 5.1). Файлы CLAUDE.md, настройки и подключённые MCP-серверы проекта действуют везде одинаково. Выбор поверхности зависит от того, где лежат ваши файлы и насколько вам комфортно в терминале.

Терминал пригодится, когда вы захотите запускать отчёты по расписанию или пользоваться всеми командами. Установка и первый запуск

Есть два пути. Если терминал вам непривычен — ставьте Desktop-приложение: оно уже включает Claude Code. Если хотите полный функционал — установите CLI. Системные требования CLI по документации: macOS 13.0+, Windows 10 1809+ или Windows Server 2019+, Ubuntu 20.04+, Debian 10+; 4 ГБ оперативной памяти и выше; подключение к интернету; страна должна входить в список поддерживаемых Anthropic.

Вариант А. Desktop-приложение

  1. Скачайте приложение. На сайте claude.com/download или по ссылкам из документации Claude Code выберите macOS или Windows (x64 либо ARM64).
  2. Войдите под своим аккаунтом claude.ai с платным планом.
  3. Откройте вкладку Code. У приложения три вкладки: Chat, Cowork и Code. Claude Code живёт во вкладке Code.
  4. Настройте сессию перед первым сообщением. Выберите окружение Local, папку проекта (например, D:\Work\SMC-reports), модель в списке рядом с кнопкой отправки и режим разрешений в селекторе режима.
  5. Напишите первую задачу обычным языком и посмотрите, как Claude её выполняет.

Вариант Б. Терминал (Windows)

  1. Откройте PowerShell. Строка приглашения начинается с PS C:\. Права администратора не нужны.
  2. Выполните команду установки: irm https://claude.ai/install.ps1 | iex. Для macOS и Linux команда другая: curl -fsSL https://claude.ai/install.sh | bash. Установка идёт без индикатора прогресса — дождитесь окончания.
  3. Откройте новое окно терминала и проверьте: claude --version должна вывести номер версии. Если команда не найдена, установщик не добавил путь в PATH — инструкция есть в разделе Troubleshoot installation документации.
  4. Рекомендуется установить Git for Windows. Без него Claude Code выполняет команды через PowerShell, с ним — через Git Bash; кроме того, Git нужен для работы с GitHub.
  5. Перейдите в рабочую папку и запустите: cd D:\Work\SMC-reports, затем claude. При первом запуске откроется браузер для входа в аккаунт. Claude Code также спросит, доверяете ли вы этой папке.
  6. Проверьте установку целиком командой claude doctor: она покажет состояние установки, ошибки в настройках и советы.

После запуска вы увидите строку ввода. Пишете задачу, Claude отвечает, показывает действия и при необходимости спрашивает разрешение (см. рис. 5.2). Нативная установка обновляется автоматически в фоне.

Осторожно. Не запускайте Claude Code прямо в домашней папке или на корне диска C:\. Создайте отдельную рабочую папку под каждую задачу (отчёты, документы SMC, сайт) и запускайте Claude там. Так он видит только то, что нужно для задачи, а ваше решение о доверии папке сохраняется.

Несколько клавиш, которые стоит запомнить сразу: Esc — остановить Claude посреди работы (сделанное сохранится); двойной Esc при пустой строке — открыть меню отката; Shift+Tab — сменить режим разрешений; символ @ — указать конкретный файл; Ctrl+V — вставить скриншот (в Windows-терминале может понадобиться Alt+V); \ и Enter — перенос строки внутри длинного запроса.

Режимы разрешений и Plan mode: сколько свободы дать Claude

Режим разрешений определяет, какие действия Claude выполняет без вашего подтверждения. Это главный рычаг безопасности и скорости одновременно (см. рис. 5.3).

Режим (в интерфейсе / в настройках)Что выполняется без вопросаКогда выбирать
Plan / planЧтение файлов и исследование; правки заблокированы, пока вы не одобрите планНачало любой новой задачи: переименование архива SMC, первый вариант отчёта
Manual / defaultТолько чтение; на каждую правку и команду — запросПапки с договорами, ценами, персональными данными; первое знакомство с инструментом
Accept edits / acceptEditsЧтение, правки файлов и файловые команды (mkdir, touch, mv, cp, rm, sed) внутри рабочей папкиВы уже одобрили план и хотите, чтобы Claude спокойно доделал работу
Auto / autoВсё, но каждое действие в фоне проверяет отдельная модель-классификатор и блокирует то, что выходит за рамки вашей задачиДлинные задачи, которым вы доверяете в целом: доработка веб-страницы, повторный прогон отчёта
Bypass permissions / bypassPermissionsВсё без проверокТолько изолированные контейнеры и виртуальные машины. Для ваших задач — не нужен

Есть ещё режим dontAsk — для скриптов и автоматизации: всё, что не разрешено заранее, просто отклоняется, Claude ни о чём не спрашивает.

Как переключать

  • Терминал: Shift+Tab по кругу: Manual → Accept edits → Plan, затем Auto, если он доступен. Текущий режим виден в строке статуса, например manual mode on или plan mode on. Запустить сразу в нужном режиме: claude --permission-mode plan.
  • Desktop: селектор режима рядом с кнопкой отправки во вкладке Code. Режим запоминается для папки (кроме Plan — он действует только на текущую сессию).
  • Веб и мобильное приложение: выпадающий список рядом с полем ввода; в мобильном приложении — кнопка +, затем Permission. В облачных сессиях доступны только Accept edits, Plan и Auto.

Важно знать. По документации, в свежих версиях Claude Code (v2.1.283 и новее) режим Auto стал стартовым по умолчанию для терминала и VS Code. Это удобно, но для папок с конфиденциальными документами разумнее стартовать в Manual. Сделать это постоянным можно в файле ~/.claude/settings.json: ключ "defaultMode": "default" внутри блока "permissions". Auto доступен не на всех моделях и может быть отключён администратором организации.

Plan mode — ваш лучший друг

В режиме планирования Claude читает файлы, исследует задачу и пишет план, но ничего не меняет. Для руководителя это идеальный формат: вы видите, что Claude собирается сделать, до того как он это сделает. Войти в Plan mode можно клавишами Shift+Tab или написав запрос с префиксом /plan, например: /plan разложи сканы SMC по папкам.

Когда план готов, Claude предлагает варианты: Yes, and use auto mode (одобрить и продолжить в Auto; если Auto недоступен, вариант называется Yes, auto-accept edits), Yes, manually approve edits (одобрить и подтверждать каждую правку) или No, keep planning (остаться в планировании и сказать, что изменить). Клавиша Ctrl+G открывает план в текстовом редакторе — его можно поправить руками.

Осторожно. Accept edits разрешает без вопроса не только правки, но и rm (удаление) и mv (перемещение) внутри рабочей папки. Перед пакетной обработкой документов делайте копию папки или работайте в Plan, а затем в Manual.

CLAUDE.md: память проекта

CLAUDE.md — обычный текстовый файл в формате Markdown, который Claude Code читает в начале каждой сессии. Это «инструкция для нового сотрудника»: кто вы, что за проект, где лежат данные, какие правила нарушать нельзя (см. рис. 5.4). Чем конкретнее и короче инструкции, тем стабильнее Claude им следует; документация рекомендует держать файл в пределах 200 строк.

Где может лежать память и на кого она действует:

  • ~/.claude/CLAUDE.md — ваши личные правила для всех проектов на этом компьютере («отвечай по-русски», «я не программист, объясняй просто»).
  • ./CLAUDE.md или ./.claude/CLAUDE.md в папке проекта — правила проекта; если папка хранится в Git, коллеги получат их вместе с проектом.
  • ./CLAUDE.local.md — ваши личные заметки по конкретному проекту, которые не нужно отдавать коллегам (добавьте в .gitignore).
  • Управляемый файл организации — если ИТ-отдел задал общие правила.

Все найденные файлы складываются вместе, а не заменяют друг друга. Внутри CLAUDE.md можно подключать другие файлы строкой вида @docs/glossary.md — удобно для глоссария терминов или списка дистрибьюторов.

  1. Создайте черновик. Наберите /init — Claude изучит папку и создаст стартовый CLAUDE.md. Если файл уже есть, команда предложит улучшения, а не перезапишет его.
  2. Допишите то, чего Claude не узнает из файлов: ваши правила форматирования, имена, запреты.
  3. Правьте по ходу. Команда /memory открывает файлы памяти для редактирования и позволяет включить или выключить автоматическую память.

Автоматическая память — это заметки, которые Claude ведёт сам: ваши исправления и предпочтения. Она хранится локально в ~/.claude/projects/<проект>/memory/, в каждую сессию загружаются первые 200 строк или 25 КБ индекса. Это контекст, а не жёсткие правила: если какое-то действие нужно запретить гарантированно, используйте настройки разрешений или хуки (о них ниже).

Как память проекта, скрипт и сохранённый навык складываются в одну автоматизацию, показано на рис. 5.5 на примере еженедельного отчёта: CLAUDE.md задаёт правила, скрипт делает расчёты и проверки, навык запускает всё одной командой. К этой схеме мы вернёмся в практической части.

Ещё один полезный префикс: восклицательный знак ! в начале строки выполняет команду оболочки напрямую и показывает результат Claude. Например, !dir input покажет список файлов в папке.

Skills — ваши собственные «кнопки»

Skill (навык) — это файл SKILL.md с инструкцией, которую Claude загружает, когда она нужна, или по вашей команде /имя-навыка. Проще говоря, это сохранённый рецепт: «как у нас собирается еженедельный отчёт» или «как оформить коммерческое предложение SG Healthcare». Навык проекта лежит в .claude/skills/<имя>/SKILL.md, личный — в ~/.claude/skills/<имя>/SKILL.md. В начале файла указываются name и description (по описанию Claude понимает, когда навык применить), ниже — инструкции обычным текстом. Старые «пользовательские команды» из .claude/commands/ теперь работают как навыки.

В Claude Code уже встроены навыки, например /loop (повторять задачу с интервалом), /code-review, /batch, /doctor. Не нужно писать навык самому: попросите Claude.

Мы только что собрали еженедельный отчёт. Оформи весь процесс как skill проекта
с именем weekly-report в .claude/skills/weekly-report/SKILL.md:
- description: "Сборка еженедельного отчёта по продажам и дебиторке из 5 Excel-файлов
  в input/. Использовать по понедельникам или по запросу «отчёт за неделю»".
- Шаги: проверить, что все 5 файлов на месте и обновлены за последнюю неделю;
  запустить weekly_report.py; проверить итоги; показать мне 5 ключевых цифр;
  подготовить черновик письма генеральному директору на русском и английском.
- Если какого-то файла нет — остановиться и сказать, какого.
Покажи текст навыка перед сохранением.

Плагины — готовые наборы

Плагин — это упаковка из нескольких навыков, агентов, хуков или MCP-серверов, которая ставится одной командой. Команда /plugin открывает меню с вкладкой Discover, где перечислены плагины из подключённых каталогов (marketplace). Официальный каталог Anthropic claude-plugins-official добавляется автоматически при первом запуске в терминале.

Для работы с документами особенно полезен репозиторий Anthropic со skills для Word, Excel, PowerPoint и PDF. По его описанию на GitHub, подключение выглядит так: /plugin marketplace add anthropics/skills, затем /plugin install document-skills@anthropic-agent-skills. Состав плагина проверьте после установки командой /skills.

Осторожно. Плагин выполняет код с вашими правами. Ставьте плагины только из официальных каталогов Anthropic или от поставщиков, которым доверяете. Каждый включённый плагин также немного расходует контекст в каждой сессии — отключайте ненужные.

Облачная сессия: репозиторий → задача → ветка → PR

Облачная сессия — это Claude Code, который работает не на вашем ноутбуке, а на изолированной виртуальной машине Anthropic (Ubuntu 24.04 с предустановленными Python, Node.js и другими инструментами). Сессия продолжается, когда вы закрыли ноутбук или сели в самолёт до Алматы, и её можно проверить с телефона. Доступна на планах Pro, Max и Team, а на Enterprise — для пользователей с премиум-местами или местами Chat + Claude Code. Отдельной платы за виртуальную машину нет, но работа расходует общие лимиты вашего плана.

Условие одно: проект должен лежать в репозитории на GitHub. Для отчётов с конфиденциальными данными это не лучший вариант, а для веб-страницы дистрибьюторов или шаблонов КП — отличный: у вас появляется история версий и возможность откатить любое изменение. Процесс показан на рис. 5.7.

  1. Подключите GitHub. Откройте claude.ai/code, войдите и следуйте подсказке Sign in with GitHub. Для приватных репозиториев установите Claude GitHub App на свой аккаунт или организацию. На планах Team и Enterprise владелец организации сначала должен включить GitHub-коннектор.
  2. Окружение. На Pro и Max создаётся окружение Default с сетевым доступом Trusted (только разрешённые домены: реестры пакетов, GitHub и т. п.). Другие уровни — None (без внешней сети), Full (любые домены) и Custom (свой список).
  3. Выберите репозиторий и ветку в селекторе под полем ввода и режим: Accept edits, Plan или Auto.
  4. Опишите задачу конкретно: какой файл, какой результат, как проверить. Каждая задача получает свою сессию и свою ветку — можно запускать несколько параллельно.
  5. Проверьте изменения. Индикатор вроде +42 −18 открывает просмотр различий. Щёлкните строку, чтобы оставить комментарий, — комментарии уйдут Claude со следующим сообщением.
  6. Создайте PR. Кнопка Create PR вверху просмотра различий: полный pull request или черновик. Сессия остаётся живой — можно продолжать правки.

Pull request (PR) — это «предложение изменений»: вы видите, что именно поменялось, и принимаете (merge) только то, что проверили. Для страницы дистрибьюторов это значит, что ни одна правка не попадёт на сайт без вашего одобрения. Если в репозитории настроены автоматические проверки, функция Auto-fix позволяет Claude следить за PR и исправлять упавшие проверки и замечания рецензентов.

Сессию можно начать и из терминала: claude --cloud "описание задачи", а готовую облачную сессию забрать к себе командой claude --teleport. Из мобильного приложения облачные сессии доступны во вкладке Code.

Совет. Если файлы должны остаться на вашем компьютере, а следить за работой хочется из командировки, используйте Remote Control: запустите claude remote-control (или /remote-control в открытой сессии) и откройте сессию во вкладке Code на телефоне. Код и файлы остаются локально, компьютер должен быть включён.

Настройки: settings.json, разрешения и хуки

Режим разрешений — это общий уровень доверия. Тонкая настройка делается в файлах settings.json (см. рис. 5.8). Файлов несколько, и у каждого своя зона действия:

  • ~/.claude/settings.json — вы, во всех проектах на этом компьютере;
  • .claude/settings.json в папке проекта — все, кто работает с проектом (если папка в Git);
  • .claude/settings.local.json — вы, только в этом проекте; Claude Code создаёт его сам, когда вы отвечаете на запрос «Yes, and don't ask again»;
  • управляемые настройки организации — их задаёт ИТ-отдел, они главнее всех остальных.

Порядок приоритета сверху вниз: организация → параметр командной строки --settings → локальные настройки проекта → общие настройки проекта → личные настройки. Списки разрешений из разных файлов объединяются. Правило deny блокирует действие в любом режиме, даже в Bypass permissions.

Пример разумных настроек для папки с отчётами (файлы настроек — строгий JSON, комментарии и лишние запятые в них недопустимы):

{
  "permissions": {
    "defaultMode": "default",
    "allow": [
      "Bash(python weekly_report.py)"
    ],
    "ask": [
      "Bash(git push *)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./contracts/**)"
    ]
  }
}

Здесь Claude может без вопроса запускать ваш скрипт отчёта, обязан спросить перед отправкой изменений в GitHub и вообще не может читать файл с паролями и папку с договорами. После сохранения выполните /status — команда покажет, какие файлы настроек загрузились. Не хочется писать JSON — используйте встроенный навык /update-config или просто попросите Claude: «Запрети себе читать папку contracts».

Хуки: гарантированные действия

Хук — это команда, которую Claude Code сам выполняет в определённый момент: до действия Claude, после него, когда Claude ждёт вашего ответа или закончил работу. В отличие от инструкций в CLAUDE.md, хук срабатывает всегда — он не зависит от того, «вспомнит» ли модель правило. Основные события:

  • PreToolUse — перед действием; может его заблокировать (например, запретить правку исходных выгрузок);
  • PostToolUse — после успешного действия (например, сделать резервную копию изменённого файла);
  • Notification — Claude отправляет уведомление, например ждёт разрешения;
  • Stop — Claude закончил ответ;
  • SessionStart — начало или возобновление сессии.

Практичный хук для занятого руководителя — уведомление на рабочем столе, когда Claude ждёт вашего решения: вы запускаете долгую задачу, переключаетесь на почту и не следите за окном. Хуки задаются в блоке "hooks" файла настроек; список действующих хуков показывает /hooks. Писать хук вручную не обязательно — опишите Claude, что нужно.

Настрой для этого проекта хук в .claude/settings.json:
1) PreToolUse: блокировать любые попытки изменить или удалить файлы в папке input/
   и выводить сообщение «input/ только для чтения».
2) Notification: показывать уведомление Windows, когда ты ждёшь моего ответа.
Объясни простыми словами, что делает каждый хук, и покажи, как проверить его работу.
Сначала покажи изменения, потом сохраняй.

Выбор модели и уровня effort

По документации Claude Code, модель по умолчанию для планов Pro, Max, Team и Enterprise — Claude Opus 5.5. Для большинства ваших задач её достаточно. Переключение — командой /model (или списком моделей в Desktop). Удобные псевдонимы: opus, sonnet, haiku, fable, а также opusplan — Opus на этапе планирования и Sonnet на этапе выполнения.

МодельСильная сторонаТипичная задача в этом разделеОценка «цена/результат» для рутины
Claude Fable 5.1Самая мощная, для самых сложных и долгих задачСложная модель отчётности с десятками источников, большой сайт5/10

Claude Haiku 5.5Самая быстрая и дешёваяПростые переименования, проверки, короткие правки8/10

Effort — это «глубина размышлений» модели: low, medium, high, xhigh, max. Для Opus 5.5, Sonnet 5.5 и Haiku 5.5 Claude Code по умолчанию использует medium. Меняется командой /effort high или стрелками в окне /model; /effort auto возвращает значение по умолчанию. Уровень max применяется только к текущей сессии. Если нужна разовая глубокая проработка одного запроса, добавьте в него слово ultrathink — настройки сессии не изменятся.

Практическое правило: высокий effort — для планирования и первой сборки (где важно ничего не упустить), средний или низкий — для повторных запусков, когда скрипт уже написан. Расход лимитов смотрите командой /usage.

Практика: пять рабочих сценариев

Ниже — сценарии на ваших реальных задачах. Цифры и имена условные. Для каждого: где запускать, какой режим, промпт и ожидаемый результат. Общий принцип: сначала Plan, потом выполнение, потом проверка.

Сценарий 1. Еженедельный отчёт из пяти Excel-файлов

Ситуация. Каждый понедельник к вам приходят пять файлов: продажи от ТОО MedLine Kazakhstan, от дистрибьютора в Ташкенте, от партнёров в Бразилии и Мексике и выгрузка дебиторки из бухгалтерии. Форматы разные: где-то даты в американском формате, где-то суммы в тенге, где-то лишняя строка заголовка. Сейчас на сводку уходит полдня.

Где и как. Desktop-приложение (Local) или терминал, папка SMC-reports с подпапками input и output, CLAUDE.md из примера выше. Режим Plan, затем Manual или Accept edits. Логика процесса — на рис. 5.5 в разделе о памяти проекта.

/plan В папке input/ лежат 5 файлов: sales_KZ.xlsx, sales_UZ.xlsx, sales_BR.xlsx,
sales_MX.xlsx и receivables.xlsx. Нужно сделать скрипт weekly_report.py,
который каждую неделю собирает из них один отчёт.

Результат: output/Weekly_Report_[ГГГГ-Wнн].xlsx с листами:
1) Summary — продажи за неделю и с начала года по странам, план/факт, % выполнения,
   изменение к прошлой неделе; отдельная строка «Seoul Medical Center».
2) By country — детализация по дистрибьюторам и моделям оборудования (УЗИ, рентген, лаборатория).
3) Receivables — дебиторка по контрагентам с разбивкой 0–30 / 31–60 / 61–90 / 90+ дней,
   просрочка выделена цветом.

Правила: суммы в USD (курс тенге и реалов возьми из листа Rates в receivables.xlsx),
input/ не изменять, при любой нестыковке столбцов — записать её в output/issues.txt,
а не угадывать. В конце скрипт должен сверить: сумма по странам = общий итог.

Сначала открой файлы, опиши мне, что в них за столбцы и какие видишь проблемы,
и предложи план. Код пиши только после моего одобрения.

Ожидаемый результат. На этапе планирования Claude перечислит столбцы каждого файла и найдёт проблемы (например: «в sales_BR.xlsx даты в формате ММ/ДД, в sales_UZ.xlsx суммы без валюты»). После одобрения он напишет скрипт на Python (обычно с библиотеками pandas и openpyxl), запустит его, покажет итоги: «Продажи за неделю $312 400, с начала года $4 870 000, просроченная дебиторка $184 000, из них 61% — один контрагент». Скрипт остаётся в папке; в следующий понедельник достаточно заменить файлы в input/ и выполнить python weekly_report.py или навык /weekly-report.

На основе output/Weekly_Report_2026-W42.xlsx сделай одностраничный отчёт для
генерального директора: output/CEO_onepager_2026-W42.pdf.
Структура: 3 главных вывода одной строкой каждый; таблица из 5 ключевых цифр
(продажи неделя/год, % плана, дебиторка, просрочка 90+); статус SMC (поставка УЗИ,
рентгена, лаборатории — по данным листа SMC); 3 риска и что я предлагаю.
Язык: русский, отдельно сделай версию на корейском для головного офиса, если сможешь
перевести корректно, иначе — на английском. Формат A4, без лишнего оформления.
Проверь, что все цифры в PDF совпадают с Excel, и покажи мне таблицу сверки.

Совет. Desktop-приложение умеет запускать запланированные задачи на вашем компьютере (компьютер должен быть включён), а команда /schedule в терминале создаёт задачи по расписанию в облаке. Для отчёта с локальными файлами подходит первый вариант; точные пункты меню проверьте в приложении — интерфейс обновляется часто.

Сценарий 2. Пакетное переименование и сортировка документов SMC

Ситуация. По проекту Seoul Medical Center за три месяца накопилось 400+ файлов: scan_0034.pdf, Договор финал ИСПР2.docx, IMG_2207.jpg, акты монтажа, сертификаты на УЗИ-аппараты, программы обучения персонала, переписка с Dr. Ahn. Нужно привести всё к единому виду: ГГГГ-ММ-ДД_Категория_Описание.расширение и разложить по папкам.

Где и как. Локально, на копии папки. Режим Plan, затем Manual. Ключевой приём — «сухой прогон»: сначала таблица «старое имя → новое имя → папка», и только после проверки — реальное переименование.

/plan В папке SMC_archive/ около 400 файлов по проекту Seoul Medical Center (Алматы).
Задача: переименовать и разложить их по структуре:
01_Договоры, 02_Поставка (подпапки УЗИ, Рентген, Лаборатория), 03_Таможня,
04_Монтаж_и_ввод, 05_Обучение_персонала, 06_Маркетинг, 07_Финансы, 99_Неразобранное.
Шаблон имени: ГГГГ-ММ-ДД_Категория_Краткое-описание.расширение
(дату бери из содержимого документа, если её нет — из даты файла).

Порядок работы:
1) Прочитай файлы (PDF и Word — текст, картинки — по содержимому, если можешь),
   ничего не меняя.
2) Сделай таблицу rename_plan.xlsx: старое имя | новое имя | папка | уверенность | почему.
   Всё, в чём уверенность низкая, отправляй в 99_Неразобранное.
3) Покажи статистику по папкам и 10 спорных случаев.
Ничего не переименовывай и не удаляй до моего письменного «ок».
Дубликаты не удалять — только пометить в таблице.

Ожидаемый результат. Таблица-план, которую вы можете открыть в Excel, поправить вручную и вернуть Claude: «Примени rename_plan.xlsx с моими правками». Claude напишет скрипт переименования, выполнит его и создаст журнал rename_log.csv, по которому всё можно вернуть назад. Если что-то пошло не так в рамках сессии, помогает /rewind, но журнал и резервная копия надёжнее.

Осторожно. Сканы без текстового слоя Claude может прочитать хуже, чем документы Word. Для них просите отдельную метку «нужна проверка» и не полагайтесь на автоматическую дату. Перед запуском убедитесь, что папка не синхронизируется с общим диском коллег, иначе массовое переименование увидят все.

Сценарий 3. Коммерческие предложения в PDF по шаблону

Ситуация. После выставки нужно отправить персональные КП десяти дистрибьюторам: в Казахстан и Узбекистан — на русском, в Бразилию и Мексику — на английском. Структура одинаковая, отличаются имя компании, контакт, модели, количество, цены, скидка, условия поставки (Incoterms) и срок действия.

Где и как. Локально. Входные данные: таблица offers.xlsx (одна строка — одно КП) и шаблон template_KP.docx с вашим фирменным оформлением. Полезно заранее поставить плагин с навыками для документов (см. раздел про плагины). Режим Plan, затем Accept edits.

Есть offers.xlsx (столбцы: company, country, contact, language, models, qty,
unit_price_usd, discount_pct, incoterms, delivery_weeks, valid_until)
и шаблон template_KP.docx с полями в фигурных скобках: {company}, {contact} и т. д.

Сделай для каждой строки коммерческое предложение в PDF:
- язык по столбцу language (ru или en), тексты для en возьми из листа EN шаблона;

Сценарий 4. Веб-страница для дистрибьюторов с калькулятором

Ограничения, типичные ошибки и безопасность данных

Ограничения

  • Claude может ошибаться. Он пишет правдоподобный, но не всегда верный код, особенно когда данные «грязные». Всегда требуйте контрольную сверку итогов и выборочно проверяйте цифры вручную, прежде чем отправлять отчёт генеральному директору.
  • Лимиты. Работа Claude Code, включая облачные сессии, расходует лимиты вашего плана вместе с обычным чатом. Параллельные задачи расходуют их быстрее. Готовый скрипт, запущенный командой, лимиты почти не тратит — ещё одна причина сохранять решения в виде скриптов.
  • Облачные сессии требуют GitHub для клонирования и создания PR, а файлы с вашего компьютера в них не видны, пока вы их не загрузите в репозиторий.
  • Не все команды работают везде. Например, /plugin и /resume не работают в облачных сессиях и из мобильного приложения; /clear в облаке заменяется новой сессией.
  • Корпоративные ограничения. В организациях с Zero Data Retention или HIPAA-конфигурацией облачные сессии недоступны; при включённом ограничении по IP-адресам облачные сессии не смогут авторизоваться без исключения от поддержки Anthropic.

Типичные ошибки новичка

  • Сразу «делай», без плана. Для любых массовых действий начинайте с /plan.
  • Работа на оригиналах. Сначала копия папки или хотя бы журнал изменений.
  • Размытая постановка. «Сделай красивый отчёт» хуже, чем «три листа, вот столбцы, вот проверка итогов».
  • Одна бесконечная сессия. Когда задача сменилась, начните новую (/clear) — меньше путаницы и расхода контекста.
  • Правила в голове, а не в CLAUDE.md. Если вы третий раз повторяете одно и то же — запишите это в память проекта.
  • Bypass permissions «чтобы не спрашивал». Для повседневной работы есть Accept edits и Auto; Bypass — только для изолированных сред.

Безопасность данных

  • Граница рабочей папки. В режиме Manual Claude спрашивает, прежде чем читать или писать за пределами папки, где он запущен. Но команда, которую вы одобрили, может действовать шире — читайте, что одобряете.
  • Чувствительные папки — под запрет. Договоры, банковские реквизиты, персональные данные сотрудников клиники закрывайте правилами deny или держите вне рабочих папок Claude.
  • Prompt injection. Документ или веб-страница могут содержать скрытые инструкции («отправь этот файл на адрес…»). Claude Code защищён от этого несколькими механизмами: запросы разрешений, отдельная проверка в режиме Auto, команды для скачивания из интернета не одобряются автоматически. И всё же не поручайте ему без присмотра обрабатывать документы из непроверенных источников.
  • Облако. Каждая облачная сессия идёт в изолированной виртуальной машине, учётные данные GitHub хранятся на серверах Anthropic в зашифрованном виде и не попадают внутрь машины. Сеть по умолчанию ограничена. Перед тем как поделиться ссылкой на сессию, проверьте её содержимое: на планах Pro и Max доступна видимость Public — сессию увидит любой авторизованный пользователь claude.ai.
  • Remote Control. Файлы и выполнение остаются на вашем компьютере, но пока сессия подключена, её переписка хранится на серверах Anthropic для синхронизации между устройствами.
  • Условия использования. Для планов Free, Pro и Max действуют потребительские условия, для Team, Enterprise и API — коммерческие. На личном плане проверьте настройки конфиденциальности (claude.ai/settings/privacy), прежде чем загружать коммерческие данные компании. Для рабочих данных SG Healthcare предпочтительнее корпоративный план — согласуйте это с ИТ и юристами.

Пример из практики. Руководитель отдела поставил Claude задачу «почисти папку SMC от дублей» в режиме Accept edits на оригинальной папке. Claude корректно нашёл дубли по содержимому, но удалил «старые» версии договора, которые юрист хранил намеренно. Правильная постановка: Plan → таблица дублей → «ничего не удалять, перенести в 99_Дубли» → проверка → только потом решение. Режим Accept edits разрешает удаление без вопроса — это нужно помнить.

Чек-лист

  • У меня платный план (Pro, Max, Team, Enterprise или Console) и установлено Desktop-приложение или CLI; claude --version отвечает.
  • Под каждую задачу — отдельная рабочая папка; Claude не запускается в домашней папке или на корне диска.
  • В папке проекта есть CLAUDE.md до 200 строк: кто я, где данные, что нельзя трогать, формат результатов.
  • Новые и массовые задачи начинаю с Plan mode; перед удалением и переименованием — копия или журнал изменений.
  • Знаю, как переключить режим (Shift+Tab или селектор), и для конфиденциальных папок стартую в Manual.
  • Чувствительные файлы закрыты правилами deny в settings.json; проверил загрузку через /status.
  • Повторяющиеся процессы сохранены как скрипты и skills (/weekly-report), а не повторяются промптом каждую неделю.
  • Отчёт перед отправкой проходит контрольную сверку итогов, а ключевые цифры я проверяю выборочно.
  • Веб-страница и шаблоны живут в GitHub; изменения попадают в работу только через PR.
  • На публичную страницу не попадают закупочные цены и данные клиентов; ссылками на облачные сессии делюсь только после проверки содержимого.

Вы хотите, чтобы Claude переименовал 400 файлов проекта SMC. С какого режима правильнее начать?

  1. Plan — Claude изучит файлы и покажет план, ничего не меняя
  2. Accept edits — так быстрее, Claude не будет переспрашивать
  3. Bypass permissions — чтобы не отвлекаться на запросы

Plan mode блокирует правки до вашего одобрения. Accept edits разрешает без вопроса mv и rm внутри папки, а Bypass permissions предназначен только для изолированных сред.

Где лучше записать правило «никогда не изменять файлы в папке input/», чтобы оно соблюдалось гарантированно?

  1. Только в тексте каждого запроса
  2. Только в CLAUDE.md
  3. В правилах разрешений или хуке PreToolUse в settings.json, а в CLAUDE.md — как пояснение

CLAUDE.md — это контекст, которому Claude старается следовать, но не жёсткое ограничение. Правило deny и хук PreToolUse срабатывают всегда, независимо от решений модели.

Что нужно для облачной сессии на claude.ai/code?

  1. Только установленный на компьютер CLI
  2. Платный план с доступом к облачным сессиям и репозиторий на GitHub
  3. Бесплатный аккаунт claude.ai и папка на рабочем столе

Облачная сессия клонирует репозиторий GitHub на виртуальную машину Anthropic, работает в отдельной ветке и позволяет создать PR. Локальные файлы ей не видны, а бесплатный план Claude Code не включает.
