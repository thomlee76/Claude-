# Claude 자율 에이전트 만들기 — 내레이션 대본

## 1. INTRO

오늘은 제가 일일이 시키지 않아도, 정해진 시간이나 조건에 맞춰 스스로 일하는 Claude 에이전트를 만드는 방법을 정리합니다.
결론부터 말씀드리면, 코딩 없이 '예약 작업 + 커넥터 + 잘 쓴 지시문' 세 가지만 있으면 오늘 바로 시작할 수 있습니다.
10분 동안 개념, 방법 비교, 5단계 설정, 안전장치, 활용 예시 순서로 보겠습니다.

## 2. 1. 개념

일반 챗봇은 제가 질문을 해야만 답하고, 대화가 끝나면 멈춥니다.
에이전트는 다릅니다. 정해진 시간이나 이벤트, 즉 트리거가 오면 스스로 시작합니다.
그리고 메일, 캘린더, 노션 같은 도구를 직접 사용해 작업을 끝낸 뒤, 결과만 저에게 보고합니다.
핵심은 '트리거 → 판단 → 도구 실행 → 결과 보고'라는 이 루프를 사람 없이 돌게 만드는 것입니다.

## 3. 2. 구성요소

에이전트는 다섯 가지 요소로 구성됩니다.
첫째, 트리거. 언제 시작할지입니다. 예를 들어 평일 아침 8시 40분, 또는 특정 메일이 왔을 때입니다.
둘째, 지시문. 무엇을 어떤 기준으로 처리하고, 결과를 어떤 형식으로 낼지 적은 업무 매뉴얼입니다.
셋째, 도구와 커넥터. Gmail, 캘린더, 노션처럼 Claude가 실제로 손을 댈 수 있는 시스템입니다.
넷째, 가드레일. 읽기는 자유롭게 하되 메일 발송이나 삭제는 사람 승인 후에만 하도록 한계를 정합니다.
다섯째, 결과 전달. 알림, 문서, 메일 초안 등 결과를 어디로 받을지 정합니다.

## 4. 3. 방법 비교

만드는 방법은 크게 세 가지입니다.
A는 Claude 자체의 예약 작업 기능입니다. 코딩이 필요 없고, 기존 구독 안에서 10~30분이면 설정됩니다.
B는 Zapier나 Make 같은 자동화 도구와 Claude를 연결하는 방식으로, '메일이 오면 즉시' 같은 이벤트 기반 자동화에 강합니다.
C는 Claude Agent SDK로 직접 코드를 짜서 서버나 GitHub Actions에서 돌리는 방식입니다. 자유도는 가장 높지만 개발 역량이 필요합니다.
추천은 명확합니다. 비개발 실무자라면 A로 시작해서 효과를 확인하고, 실시간 반응이 필요할 때 B를 추가하십시오.

## 5. 4. 실습 1단계

이제 실제로 만들어 보겠습니다. 1단계는 맡길 업무를 딱 하나 고르는 것입니다.
좋은 첫 업무는 매일 반복되고, 규칙이 명확하고, 틀려도 피해가 작으며, 결과를 제가 쉽게 검토할 수 있는 일입니다.
반대로 계약이나 가격 확정, 바로 외부로 나가는 발송 업무는 처음에는 맡기지 않는 것이 좋습니다.
예시로 '평일 아침마다 해외 파트너 메일을 요약하고, 오늘 회신이 필요한 건을 분류하고, 오늘 일정을 브리핑'하는 에이전트를 만들어 보겠습니다.

## 6. 5. 실습 2단계

2단계는 커넥터 연결입니다. 커넥터는 Claude에게 손과 발을 달아주는 것이라고 보시면 됩니다.
Claude 설정의 커넥터 메뉴에서 Gmail, Google 캘린더, 노션이나 구글 드라이브 등을 로그인 방식으로 연결합니다.
원칙은 두 가지입니다. 이 업무에 필요한 커넥터만 연결하고, 처음에는 읽기 위주로 쓰게 하는 것입니다.

## 7. 6. 실습 3단계

3단계, 가장 중요한 지시문입니다. 에이전트의 품질은 거의 이 지시문에서 결정됩니다.
역할, 입력, 처리 규칙, 출력 형식, 금지사항. 이 다섯 칸을 채우는 템플릿을 쓰시면 됩니다.
특히 분류 기준과 출력 형식을 구체적으로 쓸수록 매일 같은 품질의 결과가 나옵니다.
그리고 금지 항목에 '발송·삭제 금지, 초안까지만, 불확실하면 확인 필요 표시'를 반드시 넣으십시오.

## 8. 7. 실습 4단계

4단계는 트리거, 즉 언제 스스로 시작할지를 정하는 것입니다.
Claude 앱이나 Claude Code에서는 대화창에 '이 지시문을 평일 오전 8시 40분마다 실행하는 예약 작업으로 만들어줘'라고 말하면 됩니다.
개발자라면 서버의 cron이나 GitHub Actions 스케줄로 같은 일을 할 수 있습니다.
작은 팁으로, 9시 정각처럼 모두가 쓰는 시간보다 8시 40분처럼 살짝 어긋난 시간이 실행 지연이 적습니다.

## 9. 8. 실습 5단계

5단계는 가드레일과 테스트입니다.
읽기, 요약, 분류, 초안 작성은 자동으로 허용하고, 외부 발송·삭제·결재·결제는 반드시 사람이 승인하도록 나눕니다.
예약을 걸기 전에 먼저 수동으로 한 번 실행해서 결과를 검토하고, 마음에 안 드는 부분은 지시문을 고칩니다.
그다음 최소 2주는 '초안 모드'로 운영하면서 신뢰가 쌓이면 그때 권한을 조금씩 넓히는 것이 안전합니다.

## 10. 9. 고급

개발 역량이 있다면 Claude Agent SDK로 같은 구조를 코드로 만들 수 있습니다.
시스템 프롬프트가 지시문, allowed_tools가 가드레일 역할을 하고, 이 스크립트를 cron이나 GitHub Actions로 예약 실행하면 됩니다.
장점은 사내 ERP나 자체 데이터베이스 같은, 기본 커넥터가 없는 시스템까지 연결할 수 있다는 점입니다.

## 11. 10. 활용 예시

해외영업 실무에 바로 쓸 수 있는 에이전트 아이디어를 정리했습니다.
아침 메일·일정 브리핑은 가장 쉬우면서 체감 효과가 큽니다. 하루 30분 이상 아낄 수 있습니다.
매주 미수금과 검수 지연 점검, 매일 입찰 공고 모니터링, 매월 인허가 만료 알림도 좋은 후보입니다.
출장 2일 전에 미팅 상대별 이력과 미결 이슈를 정리해 주는 출장 브리핑도 활용도가 높습니다.
순서는 아침 브리핑을 먼저 2주 운영해 보고, 그다음 미수금 점검을 추가하는 것을 추천합니다.

## 12. 11. 흔한 실수

마지막으로 실패하는 에이전트의 공통점 다섯 가지입니다.
한 번에 너무 큰 업무를 맡기거나, '알아서 잘 해줘' 같은 모호한 지시를 주는 경우입니다.
처음부터 발송이나 삭제 권한을 주는 것, 그리고 만들어 놓고 결과를 확인하지 않는 것도 흔한 실수입니다.
또 민감한 데이터를 필요 이상으로 연결하지 않도록 주의하십시오.

## 13. 정리

정리하겠습니다. 에이전트는 트리거, 지시문, 도구, 가드레일, 결과 전달, 이 다섯 가지로 만듭니다.
오늘 하실 일은 세 가지입니다. 맡길 업무 하나를 정하고, 커넥터를 연결해 지시문으로 수동 실행을 한 번 해보십시오.
결과가 괜찮으면 평일 아침 예약 작업으로 등록하고, 2주 동안 초안 모드로 운영하면서 다듬으시면 됩니다.
작게 시작해서 신뢰를 쌓는 것, 그것이 스스로 일하는 에이전트를 성공시키는 가장 빠른 길입니다. 감사합니다.
